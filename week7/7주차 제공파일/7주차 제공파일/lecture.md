# [7주차] 컴퓨터 비전과 머신러닝 입문 — 수업 내용

> 지도학습으로 객체 검출 모델을 만들고, 새로운 영상에서 결과를 확인한다.

## 0. 수업 개요

### 수업 목표

이번 수업을 마치면 다음 내용을 설명하고 수행할 수 있어야 한다.

- 로봇에서 컴퓨터 비전이 담당하는 역할과 출력의 종류를 구분한다.
- 지도학습·비지도학습·강화학습이 사용하는 학습 신호를 예시로 설명한다.
- 이미지·정답·예측·오차·가중치의 관계와 학습·추론의 차이를 설명한다.
- 큐브 두 개와 팀이 정한 tip의 정답 라벨을 일관되게 작성한다.
- Jetson GPU에서 사전학습 YOLO Pose 모델을 파인튜닝한다.
- 새로운 장면의 실패를 확인하고 보완할 촬영 조건을 제안한다.
- 완성된 ROS 노드와 Launch를 실행하여 검출 결과를 Topic으로 확인한다.

## 1. 컴퓨터 비전

컴퓨터 비전은 영상에서 물체의 종류·위치·형태와 같은 정보를 추출하는 기술이다.
로봇이 큐브를 다루려면 먼저 어떤 큐브가 어디에 있는지 관측해야 한다.

| 문제 | 얻는 정보 | 예시 |
|---|---|---|
| 분류(Classification) | 이미지 전체의 종류 | 이 사진에 어떤 대상이 있는가 |
| 객체 검출(Detection) | 객체별 종류와 사각 영역 | 큐브 두 개의 종류와 Box |
| 분할(Segmentation) | Pixel 단위의 영역 | 물체의 외곽을 따라 구분한 영역 |
| Keypoint 예측 | 정의한 점의 위치 | 도구의 tip 위치 |

같은 장면이라도 필요한 출력에 따라 문제를 선택한다.
이번 실습은 객체별 Box와 Keypoint를 출력하는 YOLO Pose를 사용한다.

### 1.1 규칙 기반과 학습 기반

규칙 기반 처리는 사람이 색상 범위·밝기·크기와 같은 판단 조건을 작성한다.
고정된 환경에서는 유용하지만 조명이나 대상이 바뀌면 조건을 다시 조정해야 할 수 있다.

학습 기반 처리는 데이터에서 판단에 필요한 기준을 학습한다.
다양한 조건의 데이터가 도움이 되지만, 학습하지 않은 조건에서도 항상 성공하는 것은 아니다.
이번 수업은 사람이 모든 색상·형태 규칙을 작성하는 대신 이미지와 정답을 제공한다.

## 2. 세 가지 학습 방식

| 구분 | 학습에서 사용하는 정보 | 로봇·영상 예시 | 이번 수업 |
|---|---|---|---|
| 지도학습 | 입력과 그에 대응하는 정답 | 사진과 큐브 이름·Box·tip 좌표 | 직접 수집·학습·추론한다. |
| 비지도학습 | 정답 라벨 없이 주어진 데이터의 구조 | 비슷한 특징의 사진끼리 군집화 | 개념·예시만 확인한다. |
| 강화학습 | 환경에서 행동한 뒤 얻은 보상 | 큐브를 목표로 옮기는 행동 학습 | 이후 주차와의 연결만 소개한다. |

### 2.1 지도학습

이미지마다 사람이 정답을 지정한다. 정답은 이미지 전체의 이름일 수도 있고,
객체의 Box와 점 좌표일 수도 있다. 모델은 예측과 정답의 차이를 이용해 학습한다.

이번 실습의 정답은 cube1, cube2, tip의 종류·Box·Keypoint이다.
예를 들어 tip의 정답이 (335, 247)인데 모델이 (320, 220)을 예측했다면 위치가 어긋난 것이다.
이 차이를 줄이도록 학습 과정에서 가중치를 수정한다.

### 2.2 비지도학습

비지도학습은 사람이 객체 이름 같은 정답을 붙이지 않은 데이터에서 구조를 찾는다.
사진의 특징을 기준으로 유사한 사진을 묶는 군집화를 예로 들 수 있다.

이렇게 묶은 군집의 번호가 cube1·cube2라는 의미를 자동으로 갖는 것은 아니다.
군집이 무엇을 나타내는지 사람이 해석해야 할 수 있다.
이번 수업에서는 군집화 프로그램을 추가로 구현하거나 학습하지 않는다.

### 2.3 강화학습과 이후 수업

강화학습에서는 로봇이 환경을 관측하고 행동하며, 그 결과로 보상을 받는다.
목표 위치에 큐브를 가까이 옮기는 행동에 높은 보상을 주는 상황을 예로 들 수 있다.
현재 상태에서 어떤 행동이 좋은지 학습하는 과정은 이후 주차에서 다룬다.

7주차에는 카메라로 무엇이 어디에 있는지 관측한다.
이후에는 이런 관측 정보를 이용해 어떻게 행동할지 학습하는 과정으로 연결할 수 있다.
픽셀을 실제 로봇 제어에 사용하려면 좌표 변환과 안전 처리는 별도로 필요하다.

## 3. 지도학습에서 모델은 무엇을 배우는가

### 3.1 입력·정답·예측·가중치

| 요소 | 이번 실습에서의 의미 |
|---|---|
| 입력 | 카메라로 촬영한 이미지 |
| 정답(Label, Ground Truth) | 사람이 지정한 Class·Box·Keypoint |
| 예측 | 현재 모델이 출력한 Class·Box·Keypoint |
| 오차·손실(Loss) | 예측과 정답의 차이를 학습용 값으로 나타낸 것 |
| 가중치(Weights) | 모델의 계산과 판단에 사용하는 학습 가능한 값 |

신경망은 입력을 여러 계산 단계로 변환하여 예측을 만든다.
학습 과정에서 물체를 구분하거나 위치를 찾는 데 필요한 영상 특징을 구성한다.
가중치는 특정 사진의 정답 목록 자체가 아니라 새 입력을 처리할 계산에 사용한다.

학습은 다음 순서를 반복한다.

1. 현재 가중치로 입력 이미지의 결과를 예측한다.
2. 예측과 정답을 비교하여 오차를 계산한다.
3. 오차가 줄어드는 방향으로 가중치를 갱신한다.

실제 모델은 종류·Box·Keypoint에 대한 여러 차이를 함께 학습한다.
이번 수업에서는 각 손실함수의 수식이나 미분 과정을 유도하지 않는다.

### 3.2 분류와 위치 예측

cube1인지 cube2인지 고르는 출력은 종류를 맞히는 분류이다.
Box와 tip의 연속적인 좌표를 맞히는 출력은 위치값을 예측하는 회귀로 볼 수 있다.
객체 종류가 맞아도 Box나 tip 위치는 틀릴 수 있으므로 결과를 각각 확인한다.

### 3.3 학습과 추론

| 구분 | 학습 | 추론 |
|---|---|---|
| 입력 | 이미지와 정답 라벨 | 새로운 이미지 |
| 가중치 | 예측 오차를 이용해 수정한다. | 학습된 가중치를 사용한다. |
| 결과 | 학습된 모델 파일 | 현재 영상의 검출 결과 |

추론에서는 정답을 입력하지 않는다.
그렇다고 이번 모델을 비지도학습 모델이라고 부르지는 않는다.
이번 파인튜닝은 이미지와 사람이 작성한 정답을 사용하는 지도학습이다.

### 3.4 사전학습과 파인튜닝

사전학습 모델은 다른 데이터에서 이미 학습한 가중치를 갖고 있다.
이를 시작점으로 사용하면 처음부터 모든 영상 특징을 학습하는 부담을 줄일 수 있다.

이번에는 로컬 `yolo11n-pose.pt`에서 시작하여 우리 큐브와 tip 정답으로 추가 학습한다.
우리 팀이 사용하는 색 구분·tip 기준·Topcam 환경은 별도 데이터로 가르쳐야 한다.
사전학습 파일과 이번 팀의 학습 결과 파일을 혼동하지 않는다.

## 4. YOLO Pose와 이번 실습의 정답

YOLO는 영상에서 객체 종류와 위치를 예측하는 모델 계열이다.
YOLO Pose는 Box와 함께 정의한 Keypoint도 예측한다.
이번 Pose는 영상의 2D 점이며 로봇의 XYZ·Roll/Pitch/Yaw를 뜻하지 않는다.

### 4.1 클래스와 출력 점

| ID | 클래스 | 라벨링 방법 | 최종 출력 점 |
|---|---|---|---|
| 0 | cube1 | 첫 번째 색 큐브 전체 Box | 검출 Box 중심 |
| 1 | cube2 | 두 번째 색 큐브 전체 Box | 검출 Box 중심 |
| 2 | tip | 도구 주변 Box와 기준점 클릭 | 예측 Keypoint |

cube1/cube2의 실제 색은 팀이 정한다.
클래스마다 한 이미지에 객체 하나, 객체마다 Keypoint 하나를 다룬다.
같은 클래스의 여러 객체를 각각 추적하는 기능은 포함하지 않는다.

### 4.2 tip 기준과 올바른 라벨

tip은 팀이 정한 도구 끝점이나 EEF 점을 의미한다.
어느 점인지 촬영 전에 `vision.yaml`의 description에 기록한다.

| 상황 | 적절한 기준 | 피해야 할 기준 |
|---|---|---|
| 큐브 Box | 전체 큐브를 일관되게 감싼다. | 일부 면만 그려 중심이 한쪽으로 치우친다. |
| tip 주변 Box | 점을 구별할 수 있는 주변 도구 영역을 포함한다. | 점 주변의 극히 작은 영역만 매번 다르게 지정한다. |
| tip 클릭 | 모든 이미지에서 같은 물리적 점을 지정한다. | 그리퍼 중앙과 움직이는 날 끝을 섞는다. |
| 가려진 점 | 위치를 확실히 판단할 수 있으면 점을 지정하고, 위치를 모르면 점 단계에서 N을 누른다. | 위치를 모르는 점을 임의로 추측한다. |

같은 도구에 서로 다른 점을 정답으로 지정하면 모델이 배워야 할 기준도 서로 달라진다.
Box 중심과 팀이 원하는 tip이 일치한다고 가정하지 않는다.

### 4.3 영상 크기와 라벨 형식

원본 1920×1080에서 라벨링하고 저장·추론에는 640×480을 사용한다.
저장 영상은 원본을 4:3 비율로 늘려 변환한다. 미리보기의 검정 여백은 저장하지 않는다.
라벨과 추론은 동일한 변환을 사용한다.

출력의 u는 오른쪽으로, v는 아래로 증가하며 왼쪽 위는 (0, 0)이다.
원본 중앙 (960, 540)은 저장 영상에서 (320, 240)에 대응한다.
출력은 확대된 모니터 좌표나 m 단위의 로봇 좌표가 아니다.
모델 입력 설정 imgsz와 결과를 읽는 640×480 좌표도 구분한다.

라벨 한 줄은 다음 8개 값으로 구성한다.

```text
class_id center_x center_y width height keypoint_x keypoint_y visibility
```

좌표와 크기는 가로·세로 크기로 나눈 0~1 값이다.
이 도구는 visibility를 2=위치 지정, 0=위치 미상으로 저장한다.
위치 미상 점은 마지막 세 값을 `0 0 0`으로 기록한다.
객체가 아예 없으면 해당 객체의 라벨을 제외한다. 모든 객체가 없으면 빈 라벨로 저장한다.

## 5. 데이터 다양성과 검증

같은 장면을 반복 촬영한 사진이 많다고 새로운 조건에서도 잘 인식한다고 단정할 수 없다.
위치·방향·그리퍼 상태·조명·배경·가림을 바꾸어 촬영한다.
일부 객체가 없는 장면과 빈 작업판도 포함하여 없는 객체를 잘못 찾는지 확인한다.

### 5.1 Train과 Validation

Train은 가중치 학습에 사용하고 Validation은 학습 중 성능 확인과 최적 모델 선택에 사용한다.
이번 도구는 원본을 보관하고 약 80:20으로 분할한다. 같은 원본 목록과 Seed이면 같은 분할을 만든다.

서로 거의 같은 연속 사진이 양쪽에 섞이면 검증 결과가 실제보다 좋아 보일 수 있다.
학습에 사용하지 않은 새 장면을 추가로 확인한다.
현재 분할 도구는 장면 단위를 자동으로 구분하지 않으므로 촬영할 때부터 다양성을 확보한다.

### 5.2 과적합과 새로운 장면

학습한 장면에는 잘 맞지만 다른 장면에서 성능이 나쁜 현상을 과적합의 예로 이해할 수 있다.
실제 실패에는 라벨 오류, 가림, 기준 불일치 등 다른 원인도 있으므로 과적합이라고 단정하지 않는다.
오류를 보고 원인을 추정한 뒤 그 조건의 다른 이미지를 보완한다.
평가에 사용한 사진 자체를 학습에 넣고 같은 사진으로 개선을 증명하지 않는다.

### 5.3 결과 판단

- Box가 객체 전체를 제대로 감싸는지 확인한다.
- 종류가 맞더라도 tip이 다른 부위를 가리키는지 확인한다.
- 객체가 없을 때 잘못 검출하는지 확인한다.
- Confidence는 모델의 예측 점수이며 정확도 백분율이나 성공 보장이 아니다.
- Threshold를 낮추면 후보가 늘 수 있지만 틀린 결과까지 통과할 수 있다.

YOLO는 신뢰도가 낮은 후보를 제거하고, NMS로 같은 객체 주변의 중복 Box를 정리한다.
이번 수업에서는 이 직관만 이해하고 NMS 수식이나 평가 지표 계산은 다루지 않는다.

## 6. Jetson 학습과 실시간 확인

기본은 GPU 0, 최대 100 Epoch, Batch 4, Patience 20, AMP OFF이다.
Epoch는 데이터셋을 반복 학습하는 단위이고 Batch는 한 번에 처리하는 이미지 수이다.
Patience는 검증 성능 개선이 없을 때 조기 종료를 판단하는 설정이다.
설정 탐색을 별도 과제로 수행하지 않고, 메모리 부족 시 Batch를 줄이는 안내를 따른다.

1 Epoch 시험은 환경 확인용이다. 본 학습이 끝나면 최적 가중치 best.pt를 기본 모델 위치로 복사한다.
학습 결과는 `vision_pose_best.pt`와 `vision_pose_best.vision.json`을 함께 보관한다.
JSON에는 클래스·점 기준·영상 크기를 기록하므로 수집·학습·추론에서 같은 설정을 사용한다.

실시간 확인에서는 중앙·가장자리·부분 가림·조명 변화·빈 작업판을 검사한다.
실패 사례 두 개와 기대 결과·실제 결과·원인 추정·보완할 촬영 조건을 기록한다.
한 장면을 잘 맞히거나 모델 파일이 생성된 것만으로 실습 완료를 판단하지 않는다.

## 7. 완성 코드의 ROS 연결

세 단독 도구는 촬영·라벨링, 학습, 모니터링을 담당한다.
공통 모듈은 영상 변환과 검출 결과 선택을 공유한다.
코드와 패키지 설정은 완성본으로 제공하므로 학생이 빈 코드를 작성하지 않는다.

| 파일 | 역할 |
|---|---|
| yolo_dataset_tool.py | 촬영·라벨링·Train/Validation 분할 |
| yolo_finetune.py | Jetson 학습·최적 모델 복사 |
| yolo_pose_live.py | ROS 없이 실시간 결과 확인 |
| vision.yaml / vision_common.py | 설정 / 공통 영상 처리 |
| top_camera_publisher.py | /top_cam 영상 발행 |
| yolo_object_detector.py | 영상 구독·검출 결과 발행 |
| object_detection.launch.py | 두 프로세스 통합 실행 |

Camera가 영상을 발행하고 Detector는 받은 영상의 콜백에서 추론한다.
Launch는 두 프로세스를 함께 실행한다. 학습 프로그램을 ROS 노드로 바꾸는 것은 아니다.

| Topic | 메시지 타입 | 확인할 내용 |
|---|---|---|
| /top_cam | sensor_msgs/msg/Image | 640×480 영상 |
| /vision/클래스/pixel | geometry_msgs/msg/PointStamped | u, v 좌표. z=0은 깊이 측정값이 아니다. |
| /vision/클래스/detected | std_msgs/msg/Bool | 이번 영상에서 유효한 결과가 있는가 |
| /vision/클래스/confidence | std_msgs/msg/Float32 | 선택한 객체의 Box 신뢰도. 미검출은 0 |
| /vision/클래스/bbox | std_msgs/msg/Float32MultiArray | [x1, y1, x2, y2] 픽셀 |
| /vision/debug_image | sensor_msgs/msg/Image | Box·점이 표시된 확인용 영상 |

클래스에는 cube1, cube2, tip이 들어간다.
큐브는 Box 중심을 사용하고 tip은 Box·Keypoint 신뢰도를 모두 통과한 점을 사용한다.
미검출이면 detected=false와 confidence=0을 발행하고 pixel·bbox는 새로 발행하지 않는다.
pixel에는 입력 영상의 시각을 사용한다.

카메라 입력 자체가 끊기면 false 메시지도 오지 않을 수 있다.
이후 제어에 연결할 때는 검출 여부와 메시지 시각을 함께 검사해야 한다.
픽셀을 실제 로봇 위치로 변환하는 과정과 안전 제어는 이번 실습 범위에 포함하지 않는다.
영상 QoS와 Python 실행 경로는 제공된 설정을 유지한다.

## 8. 완료 기준과 텀프로젝트 연결

다음 내용을 실제 결과와 함께 설명한다.

- 이번 실습이 지도학습인 이유와 학습·추론의 차이
- 팀이 정한 큐브 색과 tip 정답의 기준
- 새 장면에서 실패한 사례 두 개와 보완할 데이터
- Launch 실행 후 pixel·detected 결과와 미검출 처리

텀프로젝트에서는 같은 도구에 클래스나 다른 점 기준을 추가할 수 있다.
설정 목록 순서가 클래스 ID이며, 기준을 바꾸면 데이터셋과 모델도 분리한다.
사용법과 확장 예시는 [실습 안내서](practice.md)의 부록을 참고한다.
비지도학습 실습과 강화학습 알고리즘 구현은 이번 주차에 추가하지 않는다.
